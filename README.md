# Pocket Smart AI — Your Smart Budget & Recommendation Assistant

A fully working personal budgeting web app: track income and expenses, set
category budgets, see analytics, get AI-style recommendations, chat with an
assistant about your own data, check whether you can afford a purchase, and
track savings goals — all in a responsive, light/dark, fintech-styled
dashboard.

**This project runs immediately with zero configuration.** It uses the
browser's local storage as its database and a built-in rule-based
recommendation engine as its AI, exactly as the "reliable local fallback"
requirement asks for. Real Supabase persistence and a real LLM are both
optional upgrades — see below.

---

## 1. Install

```bash
npm install
```

## 2. Run (development)

```bash
npm run dev
```

Open the printed local URL (usually `http://localhost:5173`).

## 3. Build for production

```bash
npm run build
npm run preview   # optional: preview the production build locally
```

The build output goes to `dist/`.

## 4. Demo login / trying it out

There is no seeded account — the app is a real multi-user auth system
(local, in your browser). To try it:

1. Open the app and click **Create one** on the login page.
2. Register with any name/email/password (this stays in your browser only).
3. Complete the one-time setup screen (income, currency, savings goal,
   categories).
4. On the Dashboard, click **Load demo data** to instantly populate
   realistic sample transactions, budgets and a savings goal for a
   presentation. Remove it anytime from Settings → Demo data.

Because everything is stored per-browser, you can create as many "accounts"
as you like (e.g. one per browser profile) to demo multi-user behaviour.

## How the AI recommendation system works

`src/services/ai.js` is the single AI service layer:

- If `VITE_AI_API_KEY` is **not** set (the default), every recommendation
  and chat answer is generated by `src/services/localRecommendations.js` —
  a deterministic, rule-based engine that reads the user's real income,
  expenses, category totals, budgets and savings goal, and turns them into
  plain-language observations (over-budget warnings, top spending
  category, month-over-month trend, savings-rate advice, etc). It never
  invents a transaction or a number that isn't in the data.
- If `VITE_AI_API_KEY` **is** set, the same data is sent to the configured
  AI endpoint (Anthropic's Messages API by default) with a system prompt
  that instructs the model to use only the given data. If that call fails
  for any reason (no network, bad key, rate limit), the app automatically
  falls back to the local engine so a demo never breaks.

The Smart Purchase Check (AI Assistant → Smart Purchase Check) is a
separate, purely rule-based evaluator: it compares the entered price
against the user's real current balance and classifies it as *Within
budget*, *Consider carefully*, or *Would significantly affect your
budget* — deliberately neutral language, with no financial guarantees.

## Environment variables

Copy `.env.example` to `.env`. Every variable is optional:

| Variable | Purpose | If left empty |
|---|---|---|
| `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` | Connects to a real Supabase project (see below) | App uses local browser storage instead |
| `VITE_AI_API_KEY` / `VITE_AI_API_URL` | Lets the AI Assistant call a real LLM | App uses the built-in local recommendation engine |

No secret key is ever imported into a component or rendered in the UI —
`ai.js` and `supabaseClient.js` are the only two files that read them, and
only from `import.meta.env`, which Vite keeps out of the git history when
`.env` is git-ignored.

## Connecting a real Supabase backend (optional)

The app is fully functional without this step. To upgrade to real,
persistent, multi-device storage:

1. Create a project at [supabase.com](https://supabase.com).
2. Open the SQL editor and run `supabase/schema.sql` from this repo — it
   creates `profiles`, `transactions`, `budgets`, `savings_goals`,
   `notifications`, and turns on Row Level Security so every user can only
   ever read or write their own rows.
3. In Supabase → Settings → API, copy the Project URL and anon public key
   into `.env` as `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`.
4. In `src/context/AuthContext.jsx` and `src/context/DataContext.jsx`,
   replace the calls to `db` (from `services/localStore.js`) with calls to
   the `supabase` client exported by `services/supabaseClient.js`, e.g.
   `supabase.from('transactions').select('*').eq('user_id', user.id)`.
   The table and column names already match 1:1 with the local store, so
   each function is a direct swap.
5. Swap `auth.register` / `auth.login` for
   `supabase.auth.signUp` / `supabase.auth.signInWithPassword`.

## Deployment

This is a static Vite build, so it deploys to any static host:

```bash
npm run build
```

- **Vercel / Netlify**: point the project at this repo, build command
  `npm run build`, output directory `dist`. Add your `.env` variables in
  the host's dashboard as project environment variables (with the same
  names, `VITE_...`).
- **Any static file host** (GitHub Pages, S3, etc.): upload the contents
  of `dist/` after building.

## Project structure

```
src/
  components/     Reusable UI: forms, cards, layout, dialogs
  pages/          One file per route (Login, Dashboard, Transactions, ...)
  context/        AuthContext, DataContext, ThemeContext, ToastContext
  services/       localStore.js (database), ai.js, localRecommendations.js,
                  supabaseClient.js (optional), demoData.js
  utils/          calculations.js, validation.js
supabase/
  schema.sql      Optional real-backend schema + RLS policies
```

## What was checked before delivery

- Every route, form, button, filter and calculation runs against real
  state derived from the local database — nothing is hardcoded.
- Add / edit / delete works for transactions, budgets and savings goals,
  with confirmation before any delete and validation on every form
  (positive amounts, required fields, valid email, matching passwords).
- Dashboard totals, budget percentages, and every chart recompute
  automatically whenever transactions, budgets or the profile change.
- Empty states are shown instead of blank screens for a brand-new account
  with no data.
- Loading states are shown for every async operation, and submit buttons
  disable while a request is in flight.
- Light and dark mode are implemented app-wide and persisted.
- The layout is responsive: a sidebar on desktop, a hamburger drawer and
  bottom navigation bar on mobile.
- Authentication is required to reach any dashboard page; logging out
  clears the session.
